Permissions for private repositories
  • Fine-grained token (recommended): Repository access → Only select repositories (the private ones you watch), Repository permissions → Contents: Read-only (releases and their files) and, for the security advisories of private repositories, Repository security advisories: Read-only. Metadata: Read-only is added automatically. Nothing else is needed – the token is never used to write.
  • Repositories of an organization: set Resource owner to the organization; the organization may have to approve the token before it works.
  • Repositories of another user (you are only a collaborator): fine-grained tokens cannot read them at all – create a token on the owner's account and set it on that repository (Repositories → its settings → GitHub token), or move the repository to an organization.
  • Classic token: needs the repo scope, which also grants write access – prefer a fine-grained token.
  • Tokens expire – set a reminder or a long expiration; an expired token shows up as an error on the repository.

Vulnerability sources

Where security advisories of the watched repositories come from.

  • GitHub security advisories Advisories maintainers publish in each repository (Security → Advisories). Uses the GitHub token.
  • OSV.dev Open vulnerability database (GitHub, Go, PyPI, RustSec … with CVE aliases). Queried for repositories with an OSV.dev package set in their settings; no account needed.

Advisories are read with the checks, at most every 6 hours. Switching a source off removes its advisories; switching it on reads it again without notifying about old ones.
