Permissions for private repositories
  • Fine-grained token (recommended): Repository access → Only select repositories (the private ones you watch), Repository permissions → Contents: Read-only (releases and their files). Metadata: Read-only is added automatically. Nothing else is needed – the token is never used to write.
  • Repositories of an organization: set Resource owner to the organization; the organization may have to approve the token before it works.
  • Repositories of another user (you are only a collaborator): fine-grained tokens cannot read them at all – create a token on the owner's account and set it on that repository (Repositories → its settings → GitHub token), or move the repository to an organization.
  • Classic token: needs the repo scope, which also grants write access – prefer a fine-grained token.
  • Tokens expire – set a reminder or a long expiration; an expired token shows up as an error on the repository.
